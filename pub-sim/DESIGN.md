# 홀덤펍 점장 — 설계

- **날짜**: 2026-11-16
- **상태**: 프로토타입 1판 (하루 영업 슬라이스). **다음은 사람이 하는 재미 게이트다** (§7)
- **관계**: 딜러마스터와 **별도 게임**이다 (사용자 결정). 판정 콘텐츠와 규칙은 딜러마스터의
  TDA 케이스 · [홀덤 테이블 프로토타입](../docs/superpowers/prototypes/nlh-table.html) · [분석](../docs/superpowers/plans/2026-11-16-nlh-sandbox-analysis.md)
  에서 가져왔다. 지금은 레포 안 `pub-sim/` 에 있고, 자체 의존이 없어 폴더째 새 저장소로 옮길 수 있다

## 실행

`pub-sim/index.html` 을 브라우저로 연다. 빌드도 서버도 필요 없다 —
three.js(r149, MIT)를 `vendor/` 에 넣어 두었다. 폰트만 Google Fonts 에서 받는다(없으면 시스템 글꼴).

## 1. 사용자 결정 (2026-11-16)

| 물은 것 | 답 |
|---|---|
| 2D 인가 3D 인가 | **3D** |
| 딜러마스터 안의 모드인가 | **별도 게임** |

## 2. 한 바퀴

```
오픈 준비 (일시정지 상태)
  참가비 2만 / 3만 / 5만 · 딜러 배치(1번 · 2번 · 휴식) · 교육 1명(실질 액션 3문제, 맞힌 만큼 정확도 +4)
영업 18:00 → 02:00 (1배속 6분, 2×·4×·일시정지)
  손님: 문 → 등록 카운터(참가비) → 바에서 대기 → 빈 자리 착석
  테이블: 핸드가 시간으로 돈다 → 끝날 때 탈락 → 리엔트리(23:00 까지) 또는 바에서 한잔 후 퇴장
  딜러: 테이블에 있으면 피로가 쌓이고 정확도가 떨어진다 → 테이블을 눌러 휴식 딜러와 교대
  홀 직원: 손님에게 걸어가 음료를 판다
  플로어 호출: 테이블 위 빨간 표시 + 오른쪽 목록 → 눌러서 판정 (판정 중에는 시간이 멈춘다)
  23:00 등록 마감 → 탈락이 빨라진다 → 합쳐서 6명 이하면 테이블 재편 → 한 명 남으면 우승(트로피)
마감 정산
  매출(참가비 · 음료) − 인건비 · 운영비 = 순이익 · 플로어 성적 · 평균 만족도 · 평판 변화 · 후기
  → 다음 날 (평판과 딜러 교육 효과가 이어진다)
```

## 3. 플로어 호출 — 판정 네 가지

| 호출 | 갈림길 | 정답 |
|---|---|---|
| 버튼 위치 오류 | 블라인드 뒤 프리플랍 액션으로 실질 액션(SA)이 성립했나 | 전 → 미스딜 · 후 → 그대로, 다음 핸드에 바로잡는다 |
| 카드 장수 이상 (1장 / 3장) | 같음 | 전 → 미스딜 · 후 → 그 좌석만 데드 |
| 레이즈 금액 이의 | 다음 카드가 깔렸나 | 전 → 최소 레이즈까지 채운다 · 후 → 그대로 선다 |
| 버튼 · 블라인드 이의 (탈락 · 착석 뒤) | 지난 핸드 D · SB · BB 와 탈락 자리 | 데드 버튼 규칙 — 좌석 지도에서 D · SB(없음 가능) · BB 를 직접 놓는다 |

- **호출 빈도는 딜러가 정한다.** 실제 정확도 = 정확도 − 피로 × 0.8. 실수 확률이 오르면 호출이 잦아진다
- **판정 결과가 경영으로 번진다.** 맞음: 평판 +1.5, 그 테이블 만족도 +8 · 틀림: 평판 −3, 만족도 −15,
  진상(빨강)이 있으면 높은 확률로 화가 나서 나간다 · 45초 안에 안 가면: 평판 −3, 딜러가 알아서 처리
- 근거는 전부 「원문 확인 전」이다 — 홀덤 테이블 분석 문서 §9 의 확인 목록과 같다

### 일부러 만들지 않은 것 (원문 확인 전)

- 새 손님이 다음 핸드의 버튼~BB 사이에 앉는 경우 → 그 자리에는 앉히지 않는다
- 헤즈업 전환 · 2~3인 테이블의 버튼 판정 → 버튼 판정은 4명 이상일 때만 낸다

## 4. 손님 · 직원

| 손님 | 색 | 리엔트리 | 음료 | 성격 |
|---|---|---|---|---|
| 단골 | 파랑 | 60% | 많이 | — |
| 초보 | 초록 | 35% | 보통 | — |
| 고수 | 보라 | 50% | 적게 | — |
| 진상 | 빨강 | 50% | 보통 | 틀린 판정에 85% 확률로 나간다 |

- 도착 간격: 참가비가 낮을수록, 평판이 높을수록 짧다. 바(대기석 7)가 차면 문 앞에서 돌아간다
- 만족도: 자리를 기다리면, 호출이 방치되면 떨어지고 음료 · 맞는 판정에 오른다. 너무 낮으면 기다리다 나간다
- 딜러 셋은 정확도 · 속도 · 친절이 다르다 (민준 86 · 서연 74 · 지호 63). 친절은 아직 효과가 없다

## 5. 합법 운영 원칙

국내 홀덤펍은 현금 시상 · 칩 환전이 불법 소지가 크다. 게임 안에서도 그대로 지킨다.

- 매출은 **참가비와 음료**뿐이다. 칩은 매출이 아니다
- 우승 상품은 **트로피와 다음 대회 시드권**. 화면 문구에 「환전 없음」을 명시한다
- 직원은 순수한 게임 요소다 — 채용 · 구인 · 매칭을 연상시키는 표현을 쓰지 않는다
  (딜러마스터 마스터 플랜의 직업안정법 주의와 같은 맥락)

## 6. 자동 점검 (Playwright · SwiftShader)

| 시나리오 | 결과 |
|---|---|
| 무작위로 답하며 하루 × 3 | 콘솔 오류 0 · 평판 50 → 15~18 · 순이익 ≈ 0 |
| 모든 호출에 정답 (`__pub.current` 를 읽어서) 하루 × 2 | 오류 0 · 평판 50 → 76~81 → 94~99 · 순이익 +24~26만 · 우승자 나옴 |
| 1280×800 · iPhone 13 스크린샷 | 데스크톱 · 세로 모바일 배치 확인 (세로에서는 카메라를 멀리 둔다) |

판정 실력이 매출과 평판으로 갈린다 — 이 게임의 뼈대가 작동한다는 최소 증거다.
호출은 하루 15~30건, 사고 셋과 버튼 판정이 대략 반반.

## 7. 재미 게이트 — 사람이 하루를 끝까지

1. **다음 날을 누르고 싶나?** — 하루가 끝났을 때 정산을 보고 한 번 더 하고 싶은가
2. **호출이 몰릴 때 긴장되나, 귀찮나?** — 두 테이블에서 동시에 부를 때
3. **딜러 교대가 결정처럼 느껴지나?** — 피로를 보고 바꾸는 판단이 의미 있나, 그냥 잊고 있나
4. **판정이 경영과 이어지는 게 보이나?** — 틀린 판정 뒤 손님이 나가는 장면이 체감되나
5. **3D 가 도움이 되나?** — 회전 · 확대를 쓰게 되나, 위에서 내려다보는 고정 화면이면 충분한가
6. **시간이 맞나?** — 1배속 6분 하루, 호출 45초 제한
