## 엔진이 하지 않는 약속 — 모르고 설계하면 잘못된 가정 위에 짓는다

전부 실측으로 확인된 것이고 의도된 동작이다. "버그다"라고 오판하지 마라.

1. **`require: ['action_validity']` 는 최선 노력이다.** 약 32.7% 핸드에서 이 축이
   안 나온다(300시드 중 98건). 오답 후보가 정답과 금액이 겹치면 출제하지 않는데,
   그게 원래 옳은 동작이다(정답이 둘인 문제를 안 내는 것). 나머지 3종
   (`calculation`·`showdown`·`procedure`)은 경성 보장이다.
   **재시도 루프는 금지다.** 안 나오면 그렇게 처리하도록 UI 가 정해라
2. **사이드팟은 `require: ['calculation']` 없이는 안 나온다.** 300시드 실측으로
   require 없이 올인 0건, 걸면 300/300
3. **판단 지점 개수는 핸드마다 다르고 0개도 가능하다.** 4축이 다 있다고 가정하지 마라
4. **`difficulty` 는 아무 효과가 없고 `rulesetId` 는 값이 하나뿐이다.**
   둘 다 의도된 상태다 — **컨트롤로 노출하지 마라**
5. **최고 표시 등급은 `senior` 다.** `gradeFrom` 은 `master` 를 반환하지만 그 조건의
   절반(B모드 이상 검출률 70%)이 3단계 범위라 미구현이다. 이상 검출을 한 번도
   시험받지 않은 학습자를 master 로 인증하지 않기로 결정했다(2026-08-29)
6. **좌석 번호가 두 벌이다.** API 인덱스는 0-based, 학습자에게 보이는 문항 문구는
   1-based(`decisions.ts` 의 `buttonSeat + 1`). 화면에서 섞으면 학습자가 오독한다
7. **등급 이동평균 창은 20이다** — `score.ts` 의 `GRADE_WINDOW` 가 정본. 호출부가
   최근 핸드를 이 개수만큼 잘라 `gradeFrom` 에 넘긴다. `gradeFrom` 은 자르지 않는다
8. **`Answer.values` 는 `(number | null)[]` 다.** 빈 칸은 `null` 로 보내라.
   0 으로 메꾸면 "0 이라고 답했다"로 채점되고, 배열을 당기면 사이드팟 답이
   메인팟 칸과 대조된다 — 둘 다 조용히 틀린 점수를 낸다

## 스펙이 이미 정한 것 — 다시 설계하지 마라

- **애니메이션 라이브러리를 쓰지 않는다.** 전부 위치 이동이라 CSS transform 으로 충분하다
- 6-max 오벌 테이블, 좌석 좌표는 **타원 파라메트릭**으로 계산(인원수 3~9 대응)
- 칩 단위 표준: 100 / 500 / 1,000 / 5,000 / 25,000 / 100,000
- 필수 3항목: **재생 속도 4단계(0.5x/1x/2x/즉시)** · **텍스트 액션 로그 병행** ·
  **`prefers-reduced-motion` 존중**(이때 로그가 주 채널)
- 실패 시 **즉시 피드백 후 정답 절차로 계속 진행**한다. 중단하지 않고, 오답 분기도
  전개하지 않는다(V1 제외). 핸드 끝나면 축별 리뷰
- 파일 배치(§8)에 컴포넌트 파일명이 이미 정해져 있다. **각 파일 400줄 상한**

## 재생이 공짜인 이유 — 설계가 이걸 노렸다

핸드는 `HandEvent[]` 이고 상태는 그 배열을 접어서(`applyEvent`) 만든다.
`stateAt(init, events, i)` 가 i 번째 시점의 상태를 그대로 준다. 되감기·재생·
속도 조절이 전부 인덱스 이동이다. **상태를 직접 고치는 설계로 되돌아가지 마라.**

## 작업 방식

- **`superpowers:brainstorming` 을 먼저 거쳐라.** 새 서브시스템이므로 architectural
  경로다 — 질문 → 접근안 2~3개 → 섹션별 설계 승인 → 스펙 문서 → `writing-plans`
- 엔진 파일(`app/src/lib/simulator/`)은 **수정하지 마라.** 2단계가 엔진 변경을
  요구한다고 판단되면 고치지 말고 **그 판단을 보고**해라 — 별도 결정이다
- 하네스(`app/src/app/simulator-harness/`)는 확인용이다. 2단계 UI 의 출발점으로
  삼지 마라 — 진단기지 제품이 아니다. 다만 **지우지도 마라**, 엔진 회귀 확인에 계속 쓴다
- 계획서를 쓰면 코드블록이 실제 파일과 어긋나지 않게 하라(R12-b). 이 레포는
  계획서를 정본으로 쓰고, 어긋난 채 두면 다음 사람이 낡은 코드를 재생성한다
- 완료 주장은 이 세션의 실제 도구 출력에만 근거해라
