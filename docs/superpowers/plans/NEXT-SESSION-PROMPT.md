### 지난 세션에 바뀐 것

1. **「첫 액션」과 「벳 크기」가 판단 하나로 합쳐졌다.** 한 화면에서 두 단계다 —

   두 판단이 원래 큐에서 붙어 나오던 것을 두 화면으로 쪼개 놨던 것이 원인이었다.

4. **노리밋은 벳 크기를 묻지 않는다** — 정답이 하나가 아니다(ADR-003). 좌석만 묻는다.

**라즈의 브링인 방향과 이후 첫 액션은 자료에 없다.** 사용자가 확정해 줬다(2026-09-03):
3번째 카드는 **가장 높은** 업카드가 브링인(스터드와 반대), 4번째부터는 **보드 로우가 가장 좋은**
좌석이 먼저. 채점 화면 출처가 `사용자 확인 (2026-09-03)` 으로 뜬다 — 자료에서 온 판단과
눈으로 구별되게 두려는 것이다. 정본이 될 표
(`참고문서/KakaoTalk_..._02.png` 하단 "Stud (GAME)(BRING-IN)(First Action)")는 제목만 찍히고
잘렸고 다음 장은 다른 날짜 시트다 — 직접 확인했다.

**PLO8(플랍게임)의 사고 처리도 자료에 없다.** `mixgame-facts.md` §3 의 노출·스텁 표는
스터드와 드로우만 다룬다. 그래서 `mkIncident` 가 `family: 'flop'` 에서 `null` 을 돌려주고
**PLO8 은 사고 없이 판단만 낸다.** 짐작으로 채우지 마라 — 자료를 받으면 그때 붙인다.

## 이 레포에서 반드시 지킬 것

1. **정답은 엔진이 낸다.** 화면 코드에 규칙 판정을 쓰지 마라. 쓰고 싶어지면 엔진이 부족한 것이다
2. **자료에 없는 것을 짐작으로 채우지 마라.** 없으면 사용자에게 묻고, 답을 받으면
   출처를 `사용자 확인 (날짜)` 로 적어라
3. **실제 브라우저에서 눈으로 봐라.** 매번 렌더·플레이로만 잡히는 결함이 나온다 —
   팟리밋 팟이 397,000 까지 부풀던 것, 노리밋에서 채점 화면이 `null.q` 로 터지던 것,
   "풀하우스이 … 투페어을 이긴다"는 조사, "K·J 투페어가 K·J 투페어를 이긴다"는 빈 해설
4. **완료는 실행 출력으로만 주장한다**
5. **말투를 검사하라.** 영어 직역·번역투가 계속 새어 나왔다. 지문을 전부 뽑아 읽어라
