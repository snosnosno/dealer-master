## 다음 종목을 붙이기 전에 반드시 고칠 것

전체 리뷰가 이 계획의 핵심 주장("새 종목은 `GameSpec` 파일 하나로 붙는다")을 추적했고,
**로우 판독에서는 거짓**이었다.

- `lib/drills/lowreading/generate.ts` 는 `(seed: string)` 만 받는다. **`GameSpec` 을 아예
  안 받고** `SEAT_COUNT = 4` 와 `QUALIFIER = 8` 을 하드코딩한다
- `app/games/[gameId]/low-reading/page.tsx` 도 `generate` 와 `record` 를 정적 import 로
  박아 두고 `gameId` 로는 경로와 라벨만 바꾼다
- 따라서 **`eval.lo` 가 있는 두 번째 종목이 생기는 순간, 그 종목의 로우 판독 화면이
  조용히 PLO8 문제를 내고 PLO8 최고기록에 쓴다.** 컴파일 오류도 실패 테스트도 없다

**라즈가 PRD §10 5단계이고 라즈는 `eval.lo` 가 있다.** 계획서가 "격자의 판정"이라 부른
바로 그 종목이 여기로 곧장 걸어 들어간다. 라즈를 붙이기 전에 `generate.ts` 가 `GameSpec` 을
받도록 고치고 페이지가 `gameId` 로 생성기·기록을 고르게 해야 한다.

진행절차 쪽은 주장이 성립한다. 다만 **스터드는 `firstToActSeat` 의 시그니처를 바꿔야 한다** —
지금 파라미터에 카드 정보가 없는데 `'lowest-upcard'` 는 누가 어떤 업카드를 들었는지로
정의된다. 스위치 채우기가 아니라 호출부 3곳(`deal.ts`·`judge.ts` 2곳)이 걸린 인터페이스
변경이다. 스터드는 그 밖에도 앤티/브링인 사이징과 좌석별 업/다운 카드 구분(`SeatState.revealed`
가 좌석당 불리언 하나여서 표현이 안 된다)이 필요하다 — 데이터 모델 4개 파일에 걸친다.

## 이 레포에서 반드시 지킬 것

1. **정답은 엔진이 낸다.** 화면 코드에 규칙 판정을 쓰지 마라
2. **시드 결정론.** 생성기·화면 어디서도 `Math.random()` 을 렌더 중에 쓰지 마라
3. **불변.** 리듀서와 순수 함수는 입력을 뮤테이트하지 않는다
4. **판정에 표시 라벨을 쓰지 마라.** `spec.betting` 코드값으로 갈라라
5. **자료에 없는 것을 짐작으로 채우지 마라.** 없으면 물어보고 출처를 `사용자 확인 (날짜)` 로 적어라
6. **실제 브라우저에서 눈으로 봐라**
7. **완료는 실행 출력으로만 주장한다**
8. **말투를 검사하라.** 이름 뒤 조사는 붙여 쓴다(`4번이다`), 명령형은 「…하세요」로 통일한다
