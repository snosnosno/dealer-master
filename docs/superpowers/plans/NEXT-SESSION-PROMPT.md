## 4단계: 로컬에서 엔진을 눈으로 확인할 수 있게 세팅

**중요 — `npm run dev` 만으로는 엔진에 대해 아무것도 안 보인다.**
확인된 사실: `app/src` 전체에서 `lib/simulator` 를 import 하는 파일이 **0개**다.
엔진은 순수 TS 라이브러리로만 존재하고 소비자가 없다. 라우트도 `app/src/app/page.tsx`
하나뿐이다. 그러니 **최소 하네스 페이지를 새로 만들어야 한다.**

만들 것 (범위를 여기서 넘기지 마라 — 이건 진짜 UI 가 아니라 확인용 하네스다):

- `app/src/app/simulator-harness/page.tsx` 정도의 라우트 하나
- 시드 입력칸 + "생성" 버튼 → `generateHand({ seed })` 호출
- 결과 렌더: 좌석·스택·버튼 위치 / 이벤트 열 / `extractDecisions(hand)` 가 낸 판단 지점
  (문항·선택지·정답·`ruleRef`) / `buildPots` 결과
- 같은 시드를 두 번 넣으면 같은 결과가 나오는 것을 눈으로 확인할 수 있게

import 는 공개 진입점에서만: `import { generateHand, extractDecisions, ... } from
'@/lib/simulator'` — `index.ts` 가 그 표면이다. `bots.ts` 와 `runBettingRound` 는
일부러 공개 표면에 없으니 끌어오지 마라.

**하네스를 만들 때 반드시 알아야 할 실측 사실** (모르면 "버그다"라고 오판한다):

- **사이드팟은 `require: ['calculation']` 없이는 안 나온다.** 300시드 실측으로 require
  없이 올인 0건·계산 판단 0건, 걸면 300/300. "가끔 섞이겠지"는 반증됐다
- **핸드마다 4축이 다 나오지 않는다.** `action_validity` 가 약 33% 핸드에서 안 나온다 —
  오답 후보가 정답과 겹치면 출제하지 않는 **의도된 동작**이다(정답이 둘인 문제를 내는
  것이 원래 결함이었다). 4축이 다 있다고 가정한 UI 를 만들지 마라
- `difficulty` 옵션은 지금 아무 효과가 없다
- 판단 지점 개수는 핸드마다 다르다. 0개인 핸드도 가능하다

세팅이 끝나면 `npm run dev` 로 띄우고 **실제로 브라우저에서 렌더되는 것을 확인한 뒤**
사용자에게 URL 과 함께 보고해라. 정적 파싱은 확인이 아니다.

`.env.local` 이 이미 있다(Supabase 설정). 하네스는 Supabase 를 안 쓰지만 Next 가
부팅하려면 필요할 수 있으니 건드리지 마라.
