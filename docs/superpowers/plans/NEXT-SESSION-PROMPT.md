# A 파트 — 2단계 잔여 이슈 점검

이전 세션이 의도적으로 미룬 것들이다. 각 항목을 **직접 확인한 뒤** 고칠지 넘길지
판단하고, 판단 근거를 보고해라. 전부 고치는 것이 목표가 아니다.

## A-1. 확실히 고쳐야 하는 것

**360px 뷰포트 가로 잘림.** `PokerTable.tsx` 의 `WIDTH = 340` 고정 + 페이지 좌우
패딩 16px씩 = 372px 필요. 375px 는 3px 여유로 통과하지만 **360px(갤럭시 등 흔한
안드로이드 폭)에서 잘린다.** 최종 리뷰가 "머지하되 크게 표시해 후속 처리하라"고
판단한 항목이다.
- 실제로 360px 로 줄여 확인부터 해라
- 테이블을 반응형으로 만들 때 `geometry.ts` 의 좌표 식은 건드리지 마라 —
  `seatOffset(i, n, radiusX, radiusY)` 가 이미 반지름을 인자로 받는다. 호출부에서
  컨테이너 폭에 따라 반지름을 주면 된다
- **`geometry.test.ts` 5개가 계속 통과해야 한다** (딜러 자리 90도 비움, 좌석 미충돌)

## A-2. 확인이 안 된 채 남은 것 — 먼저 실제로 재현해봐라

이전 세션이 계획서 체크리스트에 넣었지만 **브라우저에서 확인하지 못한 항목이다.**
"확인됐다"고 가정하지 말고 직접 봐라.

- **로그가 페이지 전체를 스크롤시키는가.** 뷰포트 높이를 ~667px 로 줄여 액션 로그가
  화면 아래로 반쯤 걸치게 한 뒤 자동 재생한다. 로그 **내부** 스크롤은 정상이지만
  **페이지**가 줄마다 따라 움직이면 결함이다.
  근거: `ActionLog.tsx` 의 `scrollIntoView` 는 명세상 스크롤 가능한 **모든 조상**을
  움직인다. `block:'nearest'` 는 로그가 뷰포트 안에 완전히 들어와 있을 때만 무해하다.
  고칠 경우 좁은 수정은 sentinel 대신 컨테이너를 직접 스크롤하는 것 —
  ref 로 `scrollTop = scrollHeight`. 조상을 건드릴 수 없다. `inline:'nearest'` 는
  축이 달라 도움이 안 된다

- **부분 점수 표시.** 숫자 2칸 문항에서 1칸만 맞히면 빨간 패널에
  `오답입니다 · 50점` 으로 나온다. 점수 값 자체는 옳다. 학습자에게 "완전히 틀림"으로
  읽히는지 눈으로 판단해라

## A-3. 고치지 말고 판단만 — 대부분 넘기는 게 맞다

이전 세션이 근거를 달아 넘긴 것들이다. **동의하지 않으면 반박해라.** 다만 반박은
근거로 해라.

| 항목 | 위치 | 이전 판단 근거 |

# B 파트 — UI 가 안 예쁜 원인과 디자인 정비

**결론부터**: 원인 후보 3개를 이미 코드에서 확인했다. 추측하지 말고 이것부터 봐라.

## B-1. 한글 폰트가 아예 안 걸려 있다 — 최우선

이게 "안 예쁨"의 가장 큰 원인일 가능성이 높다.

```
app/src/app/layout.tsx:2   import { Geist, Geist_Mono } from "next/font/google"
app/src/app/layout.tsx:7   subsets: ["latin"]      ← 한글 글리프 없음
app/src/app/globals.css:25 font-family: Arial, Helvetica, sans-serif;  ← body 를 덮어씀
```

즉 **`--font-geist-sans` 변수는 `<html>` 에 걸려 있지만 body 가 Arial 로 덮고 있고,
Geist 는 latin subset 이라 한글 글리프가 없다.** 결과적으로 모든 한글이 OS 기본
폴백(Windows 는 맑은 고딕)으로 렌더된다. 자간·굵기·크기가 디자인 의도와 무관해진다.

`12_design_system.md` §6 은 **Pretendard**(한글 웹폰트)를 쓰기로 적어 두고
"라이선스 확인 후 프로덕션 반영"을 남겨 놨다. 이번 세션이 그 미착수 항목이다.

- Pretendard 라이선스(SIL OFL)를 확인하고 보고해라
- 적용 방식을 **선택지로 제시하고 물어라**: `next/font/local` 로 self-host 할지,
  CDN 을 쓸지, `next/font/google` 대안이 있는지. 번들 크기와 CLS(레이아웃 시프트)를
  같이 보고해라. 서브셋(한글 2350자 vs 전체)도 선택지다
- `globals.css` 의 `font-family: Arial...` 을 어떻게 할지도 같이 정해라
- **웹폰트 1개는 허용된 예외다.** 그 외 패키지는 물어라

## B-2. 컬러가 토큰이 아니라 하드코딩 hex 다

컴포넌트에 raw hex 가 흩어져 있다. 실측:

```
#0F6E56 ×9   #085041 ×9   #B23A2E ×6   #EF9F27 ×5   #E1F5EE ×4
#04342C ×2   그 외 단발 8종
```

`globals.css` 의 `.sim-root` 에 `--felt`·`--felt-edge`·`--amber` 를 정의해 뒀지만
**컴포넌트가 그걸 안 쓰고 hex 를 직접 박는다.** 그래서 색을 한 번 바꾸려면 9곳을
고쳐야 하고, 다크모드 대응이 색마다 제각각이다.

- `12_design_system.md` §2 의 역할(메인 틸 / 포인트 앰버 / 뉴트럴 / 배경)에 맞춰
  토큰 이름을 정하고, Tailwind v4 `@theme` 로 노출할지 CSS 변수로 둘지 정해라
- **다크모드에서 각 색의 대비를 실측해라.** §6 이 "틸/앰버가 다크 배경에서 판독성
  유지되는지 실제 구현 시 확인"을 미결로 남겨 놨다. 이전 세션에 실제 사례가 있다 —
  `딜러(나)` 라벨이 흰 배경 흰 글씨라 안 보였고, 고친 뒤에도 zinc-500 이 다크에서
  4.10:1 로 AA 미달이라 `dark:` 변형을 따로 넣어야 했다(현재 4.83:1 / 7.55:1)
- 색 교체는 **한 번에 하나씩, 스크린샷 전후 비교**로 해라

## B-3. 목업과 대조된 적이 없다

`dealermaster_mockup.html` 에 8개 화면(랜딩/대시보드/TDA케이스/딜러교육/믹스게임/
**테이블뷰**/결과/관리자)이 있는데, 2단계 구현이 이것과 나란히 놓고 비교된 적이 없다.

- 목업의 **테이블뷰**와 **결과** 화면을 실제 `/simulator` 와 나란히 놓고 비교해라
- 어긋난 것을 **의도된 차이 / 구현 누락 / 목업이 낡음** 3가지로 분류해 보고해라.
  전부 목업에 맞추는 게 목표가 아니다 — 2단계 설계가 목업을 의도적으로 바꾼 곳이 있다
  (예: 하단 중앙을 딜러 자리로 비운 좌석 배치는 설계 §4 에서 목업을 바꾼 결정이다)
- 알려진 누락 하나: 디자인 문서 §5-2 는 "좌석별 **아바타**+이름+스택"이라고 적었는데
  구현에 아바타가 없다. 넣을지 말지 판단해라

## B-4. 디자인 문서와 제품이 어긋난 곳을 정리해라

`12_design_system.md` §3 은 "등급/스트릭은 항상 상단에 노출"이라고 하지만, 2단계는
**의도적으로 등급도 스트릭도 대시보드도 만들지 않았다**(저장이 3단계 범위라 지금
만들면 더미 데이터 화면이 된다). 문서와 현재 제품이 어긋난 상태다.

- 문서를 고쳐 "3단계에서 도입" 으로 시점을 명시할지, 아니면 다르게 정리할지 판단해라
- 코드를 문서에 맞추지 마라. **등급·스트릭을 지금 만드는 것은 금지다**

## B-5. 폰트·색을 손본 뒤 반드시 눈으로 확인

정적 파싱은 관찰이 아니다. 2단계에서 게이트 4종과 리뷰 8회를 전부 통과하고도
브라우저에서야 결함 2개가 나왔다(흰 글씨 라벨, 하이드레이션 불일치). 같은 실수를
반복하지 마라.

- `cd app && npm run dev` — **3000번에 이미 떠 있으면 그걸 써라**
  (새로 띄우면 Next 가 "Another next dev server is already running" 으로 거부한다)
- 라이트/다크 **양쪽** 확인
- `prefers-reduced-motion: reduce` 켜고도 확인 (전이 0, 재생 박자는 유지)
- 360px / 375px / 데스크톱 3폭 확인
- **콘솔 에러 0개**를 확인해라. 특히 `/simulator?seed=t2` 를 **URL 로 직접** 열어라 —
  `/` 에서 클릭해 들어가면 SSR 을 안 타서 하이드레이션 문제가 안 보인다
