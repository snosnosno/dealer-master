## 이 레포에서 반드시 지킬 것

**1. 정답은 엔진이 낸다.** 러시 코드에 규칙 판정을 쓰지 마라.
쓰고 싶어지면 그건 엔진이 부족한 것이지 러시가 특별한 게 아니다 — 그때는 엔진을 고쳐라.
축 2 가 실제로 그렇게 했다 (리오픈 규칙을 고치고, 순서 위반을 새로 넣었다).

**2. 새 기능은 프로토타입으로 재미를 먼저 확인한다.**
단일 HTML(`docs/superpowers/prototypes/`)로 만들어 사용자에게 플레이를 시키고,
통과한 뒤에만 설계 → 계획 → 승인 → 구현. 축 1·축 2 가 이 순서로 한 세션에 끝났다.

**3. 실제 브라우저에서 눈으로 봐라.**
축 1 은 렌더로만 잡힌 결함이 다섯, 축 2 는 넷이었다 (로그 대비, 한글 조사,
좌석 라벨 줄바꿈, 360px 헤더). 정적 검사로는 하나도 안 잡힌다.
Playwright 가 로컬에 있다 — MCP 서버는 이 머신에서 연결이 안 되므로
`npx playwright` 로 직접 스크립트를 돌려라.

**4. 완료는 실행 출력으로만 주장한다.**

### 엔진에서 실제로 고친 것 (다음 사람이 알아야 한다)

**`BettingContext.canRaise` 는 없어졌다.** `hasActedThisRound` 로 바뀌었고,
"레이즈할 수 있는가"는 `nlh.canReopen(ctx)` 가 판정한다. 예전에는 호출부
(`generate.ts` · `bots.ts`)가 각자 계산해 넣었고 그 사본이 규정과 어긋나 있었다.

갈라지던 지점 (BB 2,000):

```
UTG 4,700 → UTG+1 13,500 → MP 18,000 올인 → MP+1 23,000 올인
UTG+1 의 직면 증가액 = 9,500 ≥ 8,800  →  규정: 레이즈 가능 / 옛 엔진: 불가
```

### 알려진 사소한 결함

- `pot-rush.html` 에 `<meta charset>` 이 없다. `file://` 로는 열리지만 HTTP 로
  서빙하면 한글이 깨진다. `action-rush.html` 에는 있다.
- Playwright **MCP 서버**가 이 머신에서 연결 실패한다 (`CONNECT_TIMEOUT`).
  로컬 `playwright` 1.55.0 은 정상이므로 `npx playwright` 로 스크립트를 돌리면 된다.
