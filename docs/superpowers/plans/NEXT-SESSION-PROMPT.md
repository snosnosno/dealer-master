# 할 일 1 — 스플릿 팟 판정 (신규)

**지금 생성기가 버리고 있는 케이스를 살리는 것이다.** `makeWinner` 안에:

    if (ties.length > 1) return makeWinner();   // 동점은 다음 유형에서 다룬다

이 줄이 동점을 버린다. 동점이 오히려 더 좋은 문제다.

- 문제: "이 팟은 누가 나눠 갖나?" **복수 선택** — 좌석을 여러 개 누르고 확인
- 정확히 일치해야 정답. 한 명이라도 더/덜 고르면 오답
- 제한 30초
- **동점은 자연 발생 확률이 낮다.** 유도해야 한다. 쓸 만한 방법 둘:
  - 보드로 플레이 — 보드 5장이 완성 핸드(스트레이트·플러시 등)라 홀카드가 킥커로도
    안 걸리는 배치
  - 같은 랭크 페어를 두 명에게 주고 킥커가 보드에서 나오게
  - 어느 쪽이든 **실제로 동점인지 평가 함수로 확인하고** 아니면 다시 생성해라.
    "동점일 것 같은" 배치를 정답으로 삼지 마라

# 할 일 2 — 홀칩 배분 (신규)

스플릿 팟에서 팟이 나눠떨어지지 않을 때 남는 칩을 누구에게 주는가.

**규칙을 지어내지 마라. 엔진이 정본이다** — `app/src/lib/simulator/pots.ts`:

- `ODD_CHIP_UNIT = 100`
- 좌석 정렬 기준: **버튼 왼쪽 첫 좌석부터 시계방향.** 버튼 자신이 맨 뒤다
  (가장 좋은 포지션이 홀칩을 마지막에 받는다)
- 홀칩은 가장 작은 칩 단위로 남고, **버튼 왼쪽 첫 자격자부터 한 칩씩** 간다

프로토타입에 이 규칙을 그대로 옮겨라. 파일 안에서 재구현하되 엔진과 어긋나면 안 된다.

- 문제: "메인팟 X 를 N 명이 나눈다. 남는 홀칩 100 은 누구에게?"
- 좌석 선택. 제한 20초
- 버튼 위치를 화면에 반드시 표시해라 — 없으면 풀 수 없는 문제가 된다
- **TDA 조항 번호를 붙이려거든 원문으로 확인하고 붙여라.** 못 찾으면 근거를 적지
  말고 "조항 확인 전"이라고 표시해라. 번호를 지어내면 훈련생이 틀린 규칙을 배운다

# 할 일 3 — 사용자가 10문제를 풀고 판단한다

**이게 이 세션의 진짜 산출물이다.** 구현이 아니라 판단이다.

사용자에게 물을 것 셋:

1. **한 판 끝나고 "다시 하기"가 눌리나** — 이게 리텐션의 전부다
2. **다섯 유형 중 지루한 게 있나** — 있으면 빼고 나머지를 늘린다
3. **제한시간이 맞나** — 특히 사이드팟 45초, 스플릿 30초

재미가 확인되면 그때 3단계 설계 문서 → 계획서 → 구현으로 간다.
**확인이 안 되면 만들지 않는다.** C모드에서 배운 것이 정확히 그것이다.
