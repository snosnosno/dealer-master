## 프로토타입이 확립한 규칙 — 앱에서도 지켜라

이 다섯은 전부 **눈으로 보고 고친 것**이다. 옮기면서 무너뜨리지 마라.

1. **판단의 답이 곧 테이블의 진실이다.** 「브링인 1,000」이 정답이면 실제로 1,000 이 나간다.
   답과 진행이 어긋나면 그 화면은 거짓말을 하는 것이다
   - **단 팟리밋은 다르다.** 딜러가 판정하는 것은 「최대 얼마까지」이고, 실제로 얼마를 거는지는
     플레이어의 선택이다. 매 스트릿 팟까지 걸고 전원이 콜하면 팟이 스트릿마다 세 배가 된다
2. **칩은 라운드가 끝나야 수거한다.** 블라인드·브링인·벳이 좌석 앞에 남아 있다가
   라운드 끝에 팟으로 간다. **앤티만 예외** — 베팅이 아니라 딜 전에 걷는 돈이다
3. **팟은 두 곳에 있다.** 가운데 쌓인 것과 좌석 앞에 놓인 것. 규칙이 말하는 팟은 둘의 합이고,
   **딜러가 팟리밋을 계산할 때 둘을 다 세야 하는 것**이 이 종목의 교육 지점이다
4. **첫 순서 지목은 팔레트에 없다.** 딜러가 「이제 라운드를 열겠다」고 선언하는 것이 아니라
   카드가 다 나가면 그 순간이 온다. 팔레트는 일곱이다 —
   앤티 수거 · 블라인드 수거 · 번카드 · 카드 딜 · 카드 교체 · 베팅 진행 · 팟 지급
5. **첫 액션이 늘 벳이면 상황이 하나뿐이다.** 체크로 열리는 라운드가 있어야 한다(45%).
   강제 베팅이 걸린 첫 라운드만 예외다

## 검증 — 스크립트를 다시 만들어 써라

프로토타입은 이렇게 검증했다. 앱에서는 vitest 가 대신하지만 **화면은 여전히 눈으로 봐야 한다.**

- **단위 테스트**: 평가기·`chipBreak`·조사. 앱에서는 vitest 로 그대로 옮긴다
- **한 핸드 통째 추적**: 정답으로 완주시키며 로그를 전부 찍고,
  **최종 팟 == 앤티 + 라운드마다 수거한 금액의 합**을 검사한다.
  금액이 새거나 두 번 세어지면 여기서 깨진다 — 실제로 결함 다섯을 이 검사가 잡았다
- **브라우저 플레이**: `npx playwright` 로 직접 돌린다. MCP 는 이 머신에서 연결 실패한다

**한 화면만 찍어 보면 안 된다.** 프로토타입의 결함 다섯 중 넷은 화면 한 장이 멀쩡했고
**로그 두 줄 사이**가 어긋나 있었다.

## 이 레포에서 반드시 지킬 것

1. **정답은 엔진이 낸다.** 화면 코드에 규칙 판정을 쓰지 마라. 쓰고 싶어지면 엔진이 부족한 것이다
2. **자료에 없는 것을 짐작으로 채우지 마라.** 없으면 사용자에게 묻고, 답을 받으면
   출처를 `사용자 확인 (날짜)` 로 적어라
3. **실제 브라우저에서 눈으로 봐라.** 매번 렌더·플레이로만 잡히는 결함이 나온다
4. **완료는 실행 출력으로만 주장한다**
5. **말투를 검사하라.** 영어 직역·번역투가 계속 새어 나왔다. 지문을 전부 뽑아 읽어라.
   이름 뒤 조사는 붙여 쓴다(`4번이다`), 명령형은 「…하세요」로 통일한다
