## 절대 규칙 (subagent 프롬프트에 그대로 넣어라)

1. 테스트가 빨간불이면 테스트를 고치지 말고 구현을 고쳐라. 기대값은 TDA 규정에서
   나온 것이지 구현에서 나온 것이 아니다. 특히:
   - Task 5 buildPots 병합 규칙과 홀칩 버튼 기준
   - Task 8 최소 레이즈 픽스처 (1,000 이 정답, 1,200 이 아니다)
2. 확률(roll 임계값)을 조정해서 테스트를 통과시키지 마라. 계약이 확률적이면
   계약을 결정론으로 바꿔라
3. Math.random() 금지. 엔진 폴더에 react/next/@supabase import 금지
4. 계획서에 없는 것을 만들지 마라. UI·이상감지·DB 는 2·3단계다

## 직전 세션이 남긴 미해결 사항 (구현 중 반드시 처리)

1. **타입 검사 미확인.** 검토는 타입을 제거한 JS 포트로 했다. 다음 세 곳이
   TypeScript 판별 유니온 좁히기에서 걸릴 수 있다:
   - ValidationResult 에 추가한 ruling 필드
   - DecisionInput 의 correctSeats (단수 correctSeat 에서 변경)
   - Answer 의 seats (단수 seat 에서 변경)
   컴파일 오류가 나면 타입 설계를 고쳐라. 값 의미는 유지할 것

2. **계획서의 Expected 테스트 개수는 it 블록을 센 추정치다.** 실행값과 다르면
   계획서 숫자를 실제값으로 고쳐라 (테스트를 지워서 맞추지 말 것)

3. **TDA 조항 번호 3건 미검증** — 계획서에 ⚠️ 주석으로 표시돼 있다.
   TDA 2024 PDF 가 레포에 없어 확인 못 했다. PDF 를 구할 수 있으면 확정하고,
   못 구하면 ⚠️ 주석을 그대로 남겨라. 임의로 번호를 채우지 마라:
   - 딜링 순서의 근거 조항 (현재 "Rule 34" 표기, 34-A 는 버튼 위치다)
   - 홀칩 배분 조항 (기존 "Rule 20" 표기)
   - 미달 올인이 베팅을 리오픈하지 않는다는 조항
   - Rule 45-A "칩 하나를 뺀다" 가 혼합 권종에서 어느 칩인지

4. **Task 1·2 와 "완료 기준" 절은 직전 검토에서 손대지 않았다.** 문제가 없어서가
   아니라 검토 범위 밖이었다. 구현하면서 이상하면 지적해라
