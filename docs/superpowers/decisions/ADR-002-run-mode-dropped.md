# ADR-002 — 진행 모드(C모드)를 버리고 판정 중심으로 간다

- **날짜**: 2026-08-30
- **상태**: 채택
- **대체 대상**: 3단계 계획 (이상감지 B모드 → 진행 C모드 → **폐기**)
- **관련**: [DealerSim 해부](../reviews/2026-08-30-dealersim-teardown.md) · ADR-001(00_master_plan.md §3)

---

## 결정

**3단계를 "학습자가 딜러로서 핸드를 진행하는 모드"에서 "판정 중심"으로 바꾼다.**

제품 정체성이 한 줄 바뀐다 — **"딜러가 되는 법"이 아니라 "판정을 내리는 법"**.

새 순서:

| 단계 | 내용 | 역할 |
|---|---|---|
| 3단계 | **팟 판독 러시** — 매일 3분, 10문제, 개인 기록 | 리텐션 |
| 4단계 | **TDA 판정관** — 분쟁 판정, 인증 시험 대비. 저장·인증·등급이 여기 붙는다 | 지불 이유 |

---

## 맥락

2026-08-30 세션에서 C모드(진행 모드)를 설계하고 클릭 가능한 프로토타입까지 만들었다.
설계 자체는 일관됐다 — 엔진 동결 유지, 정본 스트림 재현, 오동작 차단, 이상 오버레이.
게이트도 통과했고 칩 보존도 확인됐다.

**그런데 재미가 없었다.**

## 근거

### 1. 판단 대 의식(儀式)의 비율이 나쁘다

프로토타입 기준 16스텝 중 학습자의 진짜 판단은 6개다 — 버튼 좌석, 배분 시작 좌석,
팟 분리 금액, 쇼다운 순서, 팟 지급 2회. 나머지 10스텝(번카드 ×3, 보드 오픈 ×3,
액션 진행 ×4)은 **순서만 알면 무조건 맞는 클릭**이고, 그 순서는 세 판이면 외워진다.

### 2. 의식을 걷어내면 A모드가 된다

같은 세션에서 벳 수거와 미콜 반환을 자동으로 뺐다. 둘 다 옳은 판단이었다. 그런데
그 논리를 끝까지 밀면 "판단이 필요할 때만 멈춘다"가 되고, 그건 **이미 있는
A모드(가이드)** 다.

**즉 C모드의 정체성은 의식 그 자체다.** 절차 반복이 재미의 원천이 될 수 있느냐가
전부인데, 세 판이면 소진된다. 한 번 사는 교육 소프트웨어라면 몰라도 **월 구독
제품에서는 치명적이다.**

### 3. 20년짜리 반례가 있다

DealerSim 이 정확히 같은 개념으로 2005년부터 존재했고, 20년간 제품 페이지에 오타
하나 고치지 않은 채 학원 부속품으로 남다가 2026년 여름 사라졌다. 자세한 내용은
[해부 문서](../reviews/2026-08-30-dealersim-teardown.md).

### 4. 화면이 이기는 영역은 따로 있다

딜러 훈련은 세 덩어리로 갈리고, 화면이 이기는 것은 세 번째뿐이다.

| 덩어리 | 화면이 이기나 |
|---|---|
| 손기술 (피칭·셔플·칩 커팅) | ❌ 실물로 연습한다 |
| 게임 운영·소프트스킬 | ❌ 현장에서만 |
| **규정 지식과 판정** | ✅ |

C모드는 1번을 흉내내고 있었다. 「번카드」 버튼을 누르는 것은 번카드를 태우는 것이
아니다 — 절차의 **이름**만 재현하고 **행위**는 재현하지 못한다.

## 살리는 것 / 버리는 것

**버리는 것은 이 세션에서 만든 설계뿐이다. 코드는 0줄 썼다.**

| 버린다 | 살린다 |
|---|---|
| C모드 진행 설계 · 프로토타입 | **1단계 엔진 전부** → 문제 생성기로 |
| B모드 이상감지 **단독 모드** | **2단계 테이블뷰·재생** → 상황 표시로 |
| | 디자인 시스템 · Pretendard · 브랜드 토큰 |
| | 이상 13종 목록 → 4단계 판정 상황 카탈로그로 재활용 |

세션 중 확정했던 것들도 4단계로 넘어간다 — 핸드당 이상 최소 1건, 오탐 감점,
`detectWindow` 고정 3. "언제까지 되돌릴 수 있는가"는 모드와 무관한 규정이다.

**조항 미확인 8종**(`string_bet` · `splash_pot` · `verbal_mismatch` · `under_raise` ·
`showdown_order` · `no_show` · `new_player_blind` · `muck_revival`)은 4단계 콘텐츠
작업에서 TDA 2024 원문으로 조항을 확인한다. 못 찾으면 뺀다.

---

## 3단계 — 팟 판독 러시

매일 3분. 10문제. 개인 기록. 문제 4종을 **엔진이 자동 생성**한다.

| 유형 | 생성 근거 |
|---|---|
| 팟 금액 — 칩 더미를 보고 총액 | `chipBreakdown` |
| 사이드팟 분리 — 멀티웨이 올인에서 메인/사이드 | `buildPots` |
| 승자 판정 — 쇼다운에서 누가 이기나 | `evaluateHand` |
| 지급 — 팟별로 누구에게 얼마 | `awardPots` |

- **콘텐츠 저작 비용 0.** `generateHand` 가 문제와 정답을 동시에 만든다
- 난이도는 시드 조건(인원 · 올인 수 · 스택 편차)으로 조절
- 저장·인증 없이 `localStorage` 로 시작한다 — 4단계를 기다리지 않는다

업계가 인정한 난점을 정면으로 친다: 딜러 스쿨 커리큘럼과 DealerSim 광고문이 **둘 다**
멀티웨이 사이드팟 처리를 핵심 난점으로 꼽는다.

## 4단계 — TDA 판정관

분쟁이 터진 테이블에 불려간다. 주장이 엇갈리고, 정보가 불완전하고, 되돌릴 수 없다.

- 콘텐츠 원천이 이미 손에 있다 — TDA 2024 원문 2종, 전건 대조 완료
- 인증 시험 형식에 맞춘다 — 40문항 모의고사, 90% 합격선, 10개 카테고리별 진도
- **정답이 하나가 아닌 문제를 낼 수 있다.** TDA 규정집이 "공정성을 위한 상식적 판단이
  기술 규정에 우선한다"를 명시하므로, 재량 영역이 규정으로 공인돼 있다
- 저장 · 인증 · 등급(senior 상한) · `hand_sessions` 가 여기 붙는다

---

## 결과

- 3단계 설계 문서를 쓰지 않는다. **프로토타입으로 재미를 먼저 확인한다.**
  이 세션이 가르쳐준 것이 정확히 그것이다 — 설계로는 재미를 판단할 수 없었고,
  클릭해보니 3분 만에 알았다
- 재미가 확인되면 그때 3단계 설계 → 계획서 → 구현
- 확인이 안 되면 또 만들지 않는다

## 되돌릴 조건

C모드를 다시 검토할 만한 새 정보가 나온다면:

- 실제 딜러 훈련생이 진행 모드를 반복해서 쓰더라는 관찰
- 손기술 입력 장치(실물 카드 인식 등)가 붙어 화면의 한계가 사라지는 경우

그 전에는 이 결정을 다시 열지 마라. 재조사 비용을 아끼려고 이 문서를 남긴다.
