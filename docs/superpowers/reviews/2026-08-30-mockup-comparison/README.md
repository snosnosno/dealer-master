# 목업 대조 — `dealermaster_mockup.html` vs 구현 (B-3)

2026-08-30. 2단계 UI 정비 계획서의 **B-3** 항목. 이전 세션이 남긴 유일한 미확인
항목이었다 — 커밋에도 문서에도 대조 결과가 없었다.

## 관찰 방법 (실렌더)

정적 파싱이 아니라 **실제 렌더러에서 관찰**했다.

- 렌더러: gstack `browse` (Chromium headless, 뷰포트 420×900)
- 목업: `file://dealermaster_mockup.html` → `#table` / `#result` 화면을
  `.active` 로 토글해 캡처
- 구현: `http://localhost:3000/simulator?seed=t2` (테이블뷰),
  `?seed=t9` 를 끝까지 진행해 리뷰 화면 캡처
- **콘솔 에러 0개** (`browse console --errors` — `(no console errors)`)

캡처 4장이 이 폴더에 있다.

| 파일 | 내용 |
|---|---|
| `mock-table.png` | 목업 테이블뷰 |
| `app-table.png` | 구현 `/simulator?seed=t2` (3/47, 블라인드 포스팅 직후) |
| `mock-result.png` | 목업 결과 화면 |
| `app-review.png` | 구현 핸드 종료 리뷰 (`t9`) |

## 1. 테이블뷰

### 의도된 차이 — 그대로 둔다

| 항목 | 목업 | 구현 | 근거 |
|---|---|---|---|
| 하단 중앙 좌석 | `Seat 1(나)` 가 앉아 있음 | **비어 있고 `딜러(나)` 라벨** | 2단계 설계 §4 가 목업을 바꾼 결정. 학습자는 딜러다 |
| 좌석 아바타 | 이니셜 원(`나`/`B`/`C`…) | 없음 | `2fb7015` 에서 "넣지 않기로" 결정 종결 |
| 좌석 이름 | `Seat 1`~`Seat 6` | `김도현(1)` 등 한국어 실명 + 1-based | 스포일러 방지 규율(0-based 미노출)과 학습자용 포매터 |
| 액션 로그 | 없음 | 있음 | 2단계 신설. 재생형이라 목업에 없던 요소 |
| 배속 컨트롤 | 없음 | `0.5x/1x/2x/즉시` + `3 / 47` | 2단계 신설 |

### 구현 누락 — 판단 필요

1. **칩 색 범례가 없다.** 목업 상단의 `100 / 500 / 1K / 5K / 25K / 100K` 색 배지
   줄이 구현에 없다. 칩 색은 `globals.css` 의 `--color-dm-chip-*` 로 이미 구현돼
   있고 `ChipStack` 이 쓰고 있는데, **범례가 없으면 학습자가 색↔단위를 배울 곳이
   없다.** 딜러 훈련 제품에서 칩 단위 판독은 실무 기능이다. → 넣는 쪽을 권한다.

2. **팟이 프리플롭 내내 화면에 없다.** `PokerTable.tsx:100` 이 `state.pot > 0`
   일 때만 중앙 칩스택을 그린다. 노리밋 홀덤은 스트리트가 끝날 때까지 벳이 좌석
   앞에 남으므로 **프리플롭 액션 중 `state.pot` 은 0**이고, 화면 중앙이 비어 있다.
   목업은 중앙에 `POT / 8,400` 을 항상 띄운다.
   - 엔진 동작은 정확하다 — 결함이 아니다.
   - 다만 **`POT` 이라는 글자가 화면 어디에도 없다.** 칩스택만 나오고 라벨이 없다.
   - 선택지: (a) 목업대로 `팟 + 미수집 벳 합계`를 항상 표시, (b) 라벨만 추가,
     (c) 현행 유지. 실무 딜러가 팟을 늘 소리내 확인한다는 점에서 (a)를 권한다.

3. **펠트에 레일이 없다.** 목업 펠트는 바깥 흰 테두리(레일)로 테이블처럼 보이는데,
   구현은 `inset` 그림자만 있는 평평한 타원이다. 미관 항목이라 우선순위는 낮다.

### 목업이 낡음 — 문서 쪽을 고칠 것

- 목업의 하단 CTA `좌석 배치 판정 시작` 은 "정지 화면에서 판정 시작" 모델이다.
  2단계는 재생 중 판단 지점에서 프롬프트가 뜨는 모델로 바뀌었다. 목업 문구는 이제
  제품과 맞지 않는다.

## 2. 결과 화면

목업 `#result` 는 **케이스 1건의 즉시 판정**이고, 구현 `HandReview` 는 **핸드 1개의
종합 리뷰**다. 단위가 다르므로 1:1 대조가 아니다.

### 의도된 차이

| 항목 | 목업 | 구현 |
|---|---|---|
| 단위 | 케이스 1건 (`Rule 45-A` 하나) | 핸드 1개 · 축 4종 점수 + 문항별 카드 |
| 피드백 | `AI 피드백` 카드 1개 | 문항마다 TDA 조항 + 해설 (AI 호출 없음) |
| CTA | `다음 케이스` | `다음 핸드` |

### 구현 누락 — 판단 필요

4. **`stat-row` 3칸이 통째로 없다.** 목업은 `응답 시간 / 연속 정답 / 이번 달` 을
   결과 하단에 띄운다. 구현엔 없다.
   - `연속 정답`·`이번 달` 은 **저장이 필요해 3단계 범위다.** 지금 만들면 더미다.
   - **`응답 시간` 은 지금도 가능하다** — 문항마다 제한시간 타이머가 이미 돌고 있다.
     3단계의 타이밍 채점과 직결되므로 **3단계에서 stat-row 를 통째로 도입**하는 게
     맞다. 지금은 넣지 않는다.

5. **정답일 때의 연출을 확인하지 못했다.** 캡처한 리뷰는 3문항 전부 오답(`✗`)이라
   목업의 `verdict-flip`(✓ 마크 + "정답입니다")에 대응하는 정답 상태를 못 봤다.
   다음 세션이 정답 경로로 한 번 더 봐야 한다.

### 브랜드 이탈 — 이건 고치는 쪽이다

6. **주 CTA 버튼이 검정이다.** 목업의 primary 버튼은 딥 틸(`#0F6E56`)인데 구현은
   `bg-zinc-900` 이다.

   ```
   HandReview.tsx:82      bg-zinc-900 ... dark:bg-zinc-100
   DecisionPrompt.tsx:233 bg-zinc-900 ... dark:bg-zinc-100
   ```

   `c0c4fe9`(하드코딩 hex → 브랜드 토큰) 가 **hex 만 훑고 Tailwind 기본 팔레트로
   적힌 색은 건드리지 않아서** 남았다. `app-review.png` 하단에서 검정 버튼이
   화면에서 가장 큰 색 면적을 먹는다. 브랜드 색이 아니다.

   같은 이유로 `ActionLog.tsx:43` 의 `bg-zinc-900` 로그 패널도 화면 큰 면적을
   검정으로 채운다(`app-table.png` 중단). 로그는 가독성 목적의 다크 패널이라
   의도일 수 있으나, 틸 계열(`dm-teal-900 #04342C`)로 옮기면 브랜드와 붙는다.

   → **다음 세션 첫 작업 후보.** 토큰화 작업의 잔여분이지 새 기능이 아니다.

## 결론

- 테이블뷰·결과 화면 모두 **구조적으로는 2단계 설계대로**다. 목업과 다른 곳은
  대부분 설계가 의도적으로 바꾼 지점이다.
- 지금 고칠 값어치가 있는 것은 **6번(검정 버튼·로그 패널 → 브랜드 토큰)** 하나다.
- **1번(칩 범례)** 과 **2번(팟 상시 표시)** 는 제품 결정이 필요하다.
- **4번(stat-row)** 은 3단계로 넘긴다 — 저장·타이밍이 붙어야 더미가 아니게 된다.
- **5번(정답 연출)** 은 미관찰로 남았다.

B-3 은 이로써 닫힌다.
